# Prism 4.9.0 — Griot Widget comm layer + channel-adoption groundwork

**Release date:** 2026-08-07
**Type:** feature (minor) — new shared widget spine, two new skills, headless-channel groundwork, portability repair
**Builds on:** 4.8.0 (prism-gavel drive-loop repair + generalized `digital-griot-mcp` wake channel)

## Summary

v4.9.0 extracts the per-skill widget plumbing that 4.7.0–4.8.0 grew organically into a single shared
spine — **`packages/griot-widget`** — and begins wiring the Griot surfaces (Gavel, Brainstorm) onto it.
The release also lays the *author-only* groundwork for headless/cloud channel adoption, adds two new
skills (`icm-architect`, `prism-codex-plan-sync`), and repairs a portability defect in the repo-root
`CLAUDE.md`.

This is a **build-out, not a cutover**: the widget spine is proven byte-identical to the code it
replaces, the channel-adoption epic ships as a plan with all stories still `pending`, and the live
browser companions keep their existing wake path. Nothing user-visible regresses; the new capability
is additive and gated behind follow-up work that is openly tracked.

## What changed

### Griot Widget comm layer (`packages/griot-widget/`)
A new local package decomposing the widget contract into single-purpose modules, each under ~60 lines,
with a dedicated `test.cjs` (23 assertions):
- **`render.cjs`** — the shared `render()` primitive, proven **byte-identical** to the old bespoke
  `wrapInFrame` via a real-template equivalence test; gains an `injectMeta` escape hatch so callers
  adopt it as a zero-regression drop-in without changing their meta contract (GMCL-C1).
- **`manifest.cjs`** — capability manifest for surface-aware rendering (GMCL-C2).
- **`registry.cjs`** — registry/handshake skeleton for broker registration (GMCL-C6).
- **`drive.cjs`** — the `drive()` fallback ladder: `mcp-app → cowork → :52342 → clipboard` (GMCL-C3,
  server-side).
- **`chat-cta.cjs`** — the agentic free-text chat CTA so "Other" is always a first-class affordance
  (GMCL-C4, component only — see follow-ups).

### Gavel adapter on the shared spine (`skills/prism-gavel/scripts/adapter.cjs`, GMCL-B1)
Registers Gavel on the broker and exposes a four-verb `driveVerb` matching the cockpit's card-stack/verb
model, with its own `adapter.test.cjs` (8 assertions). Gavel's local `use/role/stage/notes` mutations
are intentionally left untouched — the adapter is a transport, not a rewrite.

### Brainstorm consumes `render()` (`skills/prism-brainstorm/scripts/server.cjs`)
The Brainstorm popout server now delegates to the shared `render()` via `injectMeta` instead of its own
frame-wrapping code — byte-identical output, verified against the real `frame-template.html` with
`node --check` and the 23/23 test suite. Gavel's `server.cjs` re-points the same way.

### channel-adoption epic (author-only) — `.prism/shared/plans/2026-08-04-channel-adoption.md`
The plan + 25 stories (`.prism/stories/channel-adoption/`) for rolling the passive-bus channel transport
across the headless/cloud axis. **This run is author-only:** every story ships `status: "pending"`; no
skill is converted. The transport itself is documented in `skills/cl-plugin-structure/references/channel-patterns.md`
and reflected in `skills/fragment-sync` so the scaffolder stays in sync with the new capability.

### New skill — `skills/icm-architect`
Interpretable Context Methodology: a workspace-design skill (SKILL.md + `references/core.md`,
`references/forms.md`, and `assets/templates/*`) for structuring interpretable agent context. Self-contained;
its experiment output directory `icm/` is gitignored (regenerated by its own tooling).

### New skill — `skills/prism-codex-plan-sync`
A bidirectional codex↔prism-plan bridge: the Gavel ceremony resolves codex OPEN decisions, and an
executor-agnostic reverse channel maps changes back via git commit scopes (`forward.md`, `reverse.md`,
`mechanics.md`).

### Portability & housekeeping
- **`CLAUDE.md`** — the `@`-import changed from a hardcoded absolute machine path to the home-relative
  `@~/GriotMeta/agent-ontology/claude/CLAUDE.md`, and cp1252 mojibake was repaired (23 proper U+2014
  em-dashes restored). This resolves the portability defect that halted the prior ceremony run.
- **Doc genericization** — `fragment-sync` and `prism-codex-plan-sync` docs replaced hardcoded machine
  paths with portable placeholders (`<GriotApps>/…`).
- **`.gitignore`** — excludes `icm/`, `*.bak`, and `_to_delete/` (generated/experiment artifacts).
- **`skills/prism-closing-ceremony`** — captures the Griot Widget Contract and cloud-runnable release
  routing.

## Compatibility

Fully backward compatible. `render()` is byte-identical to the code it replaces; the channel port, its
env var, and the wake payload shape are unchanged; channel-adoption converts nothing this release. The
live browser wake path (`:52342`) is deliberately untouched.

## Known follow-ups (not in this release)

1. **Wire `chat-cta.cjs` into the live templates.** GMCL-C4 ships the component and its unit tests, but
   the CTA is not yet inserted into `prism-brainstorm`'s `frame-template.html` or `prism-gavel`'s
   `frame.html` — the free-text/agentic-chat affordance is not user-visible until a follow-up slots it in.
   The story's `done` status reflects the component, not live integration.
2. **Unify the browser-side `drive()`.** GMCL-C5 re-points the *server-side* render path; the client
   `helper.js` for both surfaces still uses its bespoke `postToChannel`/`sendEvent`, so the C3 fallback
   ladder (Cowork `sendPrompt`, clipboard) is currently reachable only from Node-side callers (Gavel's
   `adapter.cjs`), not the live browser companion. Deferred deliberately to avoid touching the working
   `:52342` wake path without a live browser eyeball.
3. **Execute channel-adoption.** The 25-story epic is authored and `pending`; conversion is a future run.

## The process finding

The two Medium findings this cycle are both **status-accuracy** issues: GMCL-C4 and GMCL-C5 were marked
`done` while a deliberately-deferred client-side half remained. The work-splitting was sound engineering
(don't disturb the live wake path without a browser eyeball), but the story status over-reported it. The
lesson carried forward from 4.8.0 holds: a story's `done` should mean *the user-visible contract is met*,
not *the code exists and unit-tests pass in isolation*. Recorded here so the follow-ups above are the
authoritative state, not the story flags.
